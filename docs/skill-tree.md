# The skill tree

## Layout

The default tree is generated by `DefaultTree.java` and written to
`config/remnants/skills_and_powers/skill_tree.default.json` on every start, for reference.

- **Inner ring:** six origin nodes joined by two neutral "Remnant Path" nodes each, so neighbouring
  schools are three steps apart.
- **Each school** has three branches. Every branch passes through two **notable wheels**: a ring of
  six themed minor nodes around a named notable.
- **Five abilities per school:** one next to the origin, one on each branch, and a two-point
  **ultimate** at the far end of the middle branch, behind the school's **Mastery** notable.
- **Two keystones per school**, at the ends of the outer branches.
- **Hybrid bridges** join neighbouring schools at two radii, each with a notable that mixes both
  elements (Plasma Arc, Black Ice, Phoenix Ash and others).

Totals: 522 nodes, 54 notables, 30 abilities and 12 keystones.

## Rules

- Your allocation must be one connected group that contains an origin node.
- A node can only be refunded if the rest stays connected (refund outer nodes first).
- The server applies a whole staged build at once. If any check fails, nothing changes.

## Writing a custom tree

1. Copy `skill_tree.default.json` to `skill_tree.json` (it is created on first start) and edit it.
2. Set `"use_custom_tree": true` in `general.json` under `tree`.
3. Run `/powers reload`. Every player receives the new tree. Allocations that no longer fit are
   refunded and the player is told why.

Clients never need a copy of the tree: the server sends it on join and on reload.

### Node format

```json
{
  "id": "pyro.l1.notable",
  "type": "notable",
  "school": "pyromancy",
  "name": "Searing Focus",
  "x": -138.6, "y": -432.7,
  "icon": "minecraft:blaze_powder",
  "stats": { "fire_damage": 15, "crit_chance": 5 },
  "flavor": "Hold the flame until it is white.",
  "links": ["pyro.l1.ring1", "pyro.l1.ring5"]
}
```

| Field | Meaning |
| --- | --- |
| `id` | Unique id. Build codes refer to nodes by their position in the file, so append new nodes at the end to keep old codes working |
| `type` | `start`, `minor`, `notable`, `ability` or `keystone`. Only `start` nodes can begin a build |
| `school` | `pyromancy`, `stormcalling`, `umbral`, `tidecalling`, `earthshaping`, `verdance` or `none`. Sets the color |
| `x`, `y` | Position in tree units. The default tree spans about ±1000 |
| `icon` | Any item id, drawn inside the node |
| `stats` | Stat ids and values. See [stats](stats.md) |
| `ability` | Ability id this node unlocks. See [abilities](abilities.md) |
| `keystone` | Keystone id this node enables. See [keystones](keystones.md) |
| `cost` | Skill points to allocate (default 1) |
| `requires` | `{"ras_level": 20}` and/or `{"power_level": 10}` |
| `links` | Ids of connected nodes. Links work in both directions, so list each link once |
| `on_allocate`, `on_refund` | Server commands run when the node is confirmed or refunded. `{player}` and `{uuid}` are replaced |
| `flavor` | Italic lore line |

Problems are written to the server log on load. A tree with no origin node, or with links to missing
nodes, is rejected and the built-in tree is used instead.

## Build codes

The **Share** button copies a code such as `RSP1-BWJpfwwAEgEBAQEBAQEEAQE`. It holds the node list
and a checksum of the tree. Pasting a code imports it as a **plan**: nothing is spent until you use
the plan. A code made for a different tree still imports what it can, with a warning.
`/powers build [player]` prints a clickable code.
